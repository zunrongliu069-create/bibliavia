# Scriptora lesson-flow audit — 2026-08-25

## Scope

Today → lesson introduction → exercise → tolerant answer assessment → reward and next verse.

## Steps

1. **Today — mostly healthy.** The main review action is discoverable and the reward/progress systems are visible. The four-item HUD truncates its labels at this viewport, and the page carries several competing progress summaries before the primary practice action.
2. **Lesson introduction — healthy.** The verse, exercise count, stage reward, start, finish, and close controls provide a clear beginning and exit.
3. **Exercise — healthy.** The stage, verse reference, mastery values, prompt, and primary action have a clear order. Some secondary text is small and low-contrast against the illustrated background.
4. **Answer assessment — functional with a clarity gap.** Capitalization, punctuation, and a one-letter spelling slip were correctly accepted at 99%. Automatic difficulty plus manual override works. The screen does not yet show exactly which typed word differed from the source, and the override controls can fall below the viewport.
5. **Reward and next verse — healthy.** The reward is concrete and the next action names Romans 1:4, so the lesson has a clear stop and continuation point.

## Priority recommendations

1. Add a word-level comparison that highlights the user's changed, missing, and extra words.
2. Add a first-run language and translation choice, then keep interface language, Bible language, and audio language visibly distinct and synchronized.
3. Base automatic difficulty on recent attempts as well as the current score, and never use reading speed as proof of recall.
4. Reduce the Today screen's competing summaries and make the top HUD responsive so labels never truncate.
5. Keep the primary result action fixed above the fold; place manual difficulty override behind a compact “Adjust” control.
6. Verify keyboard focus, screen-reader announcements, reduced motion, text scaling, and color contrast separately; screenshots cannot prove those behaviors.

## Evidence limits

The screenshots support visible hierarchy, copy, responsiveness, and state-transition observations only. They do not establish complete WCAG compliance, speech-recognition quality, audio quality, or behavior on native iOS and Android.
